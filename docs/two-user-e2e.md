# 本番2ユーザー通しテスト

実施日: 2026-10-05

## 目的

本番環境で、2人の利用者による同行募集から評価・安全対応までの一連の動作を確認する。テスト投稿には本文の先頭に `[公開前テスト]` を付け、完了後に募集を終了する。

## 確認済み

- アカウントAの認証済みセッションでマイページが表示される。
- プロフィールと項目別公開設定が読み込まれる。
- 参戦予定の公演から同行募集フォームを開ける。
- 同行募集フォームに募集タイプ、希望性別、同担、希望年齢、募集締切、コメントが表示される。
- DM一覧、安全設定・募集管理、退会確認画面を開ける。
- アカウントAには現在、同行募集、DM、ブロック、通報、同行評価がない。
- 退会画面は削除対象、共通認証を残すこと、管理者の注意事項を表示する。
- アカウントAが `[公開前テスト]` の同行募集を本番で投稿した。
- 自分の募集管理に「募集中」として表示される。
- 公演ページに「募集中1件」と募集本文、自分の募集、募集終了の操作が表示される。
- 投稿確認中に発見したSupabase結合エラーを修正し、取得失敗を0件と誤表示しないようにした。
- アカウントBを確認メール経由で作成し、初回プロフィールと通知OFFの設定を保存できる。
- アカウントBからM!LK宮城公演の募集とアカウントAの表示名・募集条件・本文が見える。
- 募集の「メッセージを送る」からAとのDMを開始できる。
- BからAへテストメッセージを送信し、AのDM一覧とチャット本文の両方で受信を確認できる。
- Aがチャットを開いた後も、Bの送信画面には既読状態が表示されない。
- BからAの公開プロフィールを開き、公開中の表示名・ユーザーID・都道府県と公開活動の集計が表示される。
- AからBへ返信し、Bのチャット画面で受信を確認できる。
- 同行者決定時に発見したRLSの循環を、公開範囲を変えずに専用の検証関数へ分離して修正した。
- AがBを同行者に決定すると募集が自動で終了し、双方のチャットに「同行者として成立しています」と表示される。
- Bの公演ページでは成立済み募集が「同行成立」と表示され、「メッセージを送る」が消えて新規DMを開始できない。
- BからAを対象に `[公開前テスト]` の通報を作成し、安全設定に理由、受付状態、対象、詳細が表示される。
- 通報のRLSは、通報者本人またはカタログ管理者だけが閲覧できる。今回の対象Aはカタログ管理者でもあるため、一般ユーザーである通報対象本人から詳細が見えないことの画面確認は未実施。
- BがAをブロックすると、BのDM一覧から会話が消え、公演ページからAの成立済み募集が消える。
- ブロック中に会話URLを直接開いても利用不可の案内になり、入力欄は表示されない。
- ブロック中のメッセージ送信をサーバー側でも拒否し、テスト用メッセージが保存されていないことを確認した。
- BがAのブロックを解除すると、安全設定から対象が消え、DM一覧、会話内容、成立状態、公演ページの成立済み募集が復元する。
- ブロック解除後は両方向ともブロックなしであることを確認した。RLSは自分が作成したブロックだけを解除できるため、相手側のブロックを変更できない。

## DB での検証（2026-10-09）

`db/test-p0-review-report-withdraw.sql` を本番DBで実行し、21項目が通過した。テストデータはすべてロールバック済みで、残っていないことも確認した。どのユーザーも、一般ユーザーとして（`authenticated` ロールと各ユーザーのIDで）操作した。

- 同行評価：開催前の評価、なりすまし、当事者以外による評価、同じ評価の重複投稿はすべて拒否された。開催後は成立した2人の間で評価できる。評価者は自分の評価を非表示にできず、管理者は理由を付けて非表示にできる。非表示の評価は第三者には見えず、評価された本人には見える。
- 通報（対象は管理者でない一般ユーザー）：なりすまし通報は拒否された。通報者は自分の通報を読める。対象本人と第三者には、通報・証拠・対応履歴のどれも見えない。対象本人は状態を変更できず、通報について通知も届かない。
- 退会：確認文言が違うときは拒否された。退会者のプロフィール・会話・DM・評価・同行成立はすべて削除された。共通認証のユーザー、相手のデータ、student-chat の行数は変わらなかった。
- **要対応**：通報者が退会すると、その通報も連鎖削除される（対象者が退会した場合も同じ）。プライバシーポリシーの「通報記録は対応終了後2年保存」と合っていない。
