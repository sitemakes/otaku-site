次の内容を設計してください。**コードの実装はしないでください。**

依頼内容: $ARGUMENTS

## 手順
1. CLAUDE.md、関連するコード、既存の docs/PLAN.md（あれば）を読み、現状を把握する
2. 不明点や判断が分かれる点があれば、設計を書く前に質問する
3. docs/PLAN.md を以下の構成で書く（既存の PLAN.md があれば、完了済みステップを残して新しい内容に更新する）

## PLAN.md の構成
- **目的**: 何のために何を作るか（2〜3行）
- **完了条件**: 動作として確認できる条件の箇条書き
- **スコープ外**: 今回やらないこと
- **ステップ**: 1回で Codex に渡せる大きさに分ける。各ステップに以下を書く
  - 変更・追加するファイル（パス）
  - 各ファイルでやること（関数名・型・処理の流れ）
  - 確認方法（必ず `bash scripts/check.sh` を含める。画面確認が必要なら手順も書く）
  - 状態: `未着手` / `完了`
- **UI がある場合のみ**: 画面ごとの要素の並び、`theme.css` のどの変数・クラスを使うか、スマートフォン幅での挙動。
  必要なら docs/mockups/ に HTML のモックアップを置き、PLAN.md から参照する

## このリポジトリ固有の注意（CLAUDE.md 参照）
- DB 変更があるときは、フロントとは **別のステップ** にする。
  そのステップの成果物は `db/` に追加する SQL ファイル（適用手順・戻し手順つき）とし、適用は人間が行うと明記する。
  フロントのステップは「DB 適用後」に着手する順番で並べる
- 権限制御は RLS・トリガーで行う設計にする（ボタンを隠すだけの設計にしない）
- 「変更してはいけない重要部分」に触れる設計になる場合は、書く前にユーザーに確認する

書き終えたら、PLAN.md の要点を短くまとめ、「確認してOKなら `/delegate 1` で実装を Codex に渡せます」と伝えてください。
