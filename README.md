# OTAKU LIVE MVP

アイドル現場を中心に、参戦予定・同行募集・DMへつなぐMVPです。

## 現在できること
- 公演一覧・検索・詳細、ログイン、プロフィール、推し登録
- 参戦予定、同行募集、当事者間のDM
- 管理者によるグループ・メンバー・公演の手動登録と公開

## 情報の登録手順
1. 指定済みの管理者アカウントでログインし、マイページの「グループ・メンバー・公演を管理」を開く（`admin.html`）。
2. 実在データを選び、グループを下書き保存。識別名は半角英小文字・数字・ハイフンで一意にする。
3. 公式サイト、主催者、会場、公式販売ページで事実を確認。個別情報を確認できるHTTPSの出典URLと出典種類を入力する。
4. 「今回の入力内容を出典と照合した」をチェックし、公開して保存する。
5. メンバーや公演を登録し、先に公開したグループに紐づける。公演時刻は日本時間。終演未定は空欄。
6. 修正も同じ編集画面から保存。公開中の内容は毎回再確認が必要。中止・誤情報は「非公開・保管」にする。公開中の子データがあるグループは、子データを先に非公開にする。

下書き・非公開データは管理者以外に見えません。ホームと推し選択は実在データが初期表示です。実在情報はまだ投入していません。「DEMO」チェックで既存の動作確認データを利用できます。公演の公開後も最新の開催状況は出典を確認してください。合同公演は代表グループを1組紐づけるMVP仕様です。

自動取得・スクレイピング・画像や紹介文の転載は行いません。出典URLの形式検証は、リンク先が公式であることを保証しません。担当者が内容・運営主体を確認します。変更履歴には変更前後の値と操作アカウントIDを記録します。画面の絞り込みは読み込み済みの行を対象とし、50件ごとに追加読み込みできます。

## データ
Supabaseプロジェクト `pfyvsweuvdnpmvabfflh`（表示名 student-chat）内の `otaku_*` テーブル群を使用します。物理的に別プロジェクトではありません。student-chat のテーブル・ポリシー、共通Auth設定は変更しません。

`db/catalog-admin.sql` は管理APIの migration `otaku_catalog_admin` として適用済みのSQLです。既存カタログ3テーブルだけの公開ルールを更新し、専用管理者テーブル、検証、監査を追加します。新規環境では既存MVPのスキーマが先に必要です。適用済み環境でこのファイルを再実行しないでください。

管理者は `otaku_catalog_admins` の許可リストで管理します。ブラウザから追加・削除はできません。管理者の追加はDB管理者が、本人を確認した登録済みAuthユーザーのUUIDのみを登録します。プロフィールや user_metadata で権限は付与しません。権限削除はこの専用テーブルの行を削除し、他アプリの権限には触れません。

カタログの物理削除権限はブラウザに付与しません。既存のDEMO区分とIDは変更不可、同一グループのメンバー名と公演の組み合わせは一意です。更新は revision により上書き競合を検知します。監査用の限定された private trigger 以外は SECURITY INVOKER。サービスキーはブラウザに不要です。カタログの管理APIからの書き込みにも、監査のため認可済みユーザーの操作主体が必要です。

## 検証
- `node --test tests/catalog.test.cjs`：出典URL、公開要件、日時、入力検証。
- `db/test-catalog.sql`：管理者・一般ユーザー・未ログインの実DB権限、公開・非公開、重複、監査、競合。すべてトランザクション内で実行しロールバックするためテストデータは残らない。最低1名の管理者登録が必要。
- ローカルブラウザ：未ログイン時の管理画面拒否、実SupabaseからのDEMO取得・公演詳細、ローカルの模擬接続による3種類の登録・公開条件・日本時間再表示を確認。管理者の実ログインによる本番ブラウザ保存は別途確認する。
- カタログ以外の既存RLSポリシーのハッシュは変更前後で一致。

## デプロイ
GitHub `sitemakes/otaku-site` を Vercel `otaku-live-mvp` に接続した静的サイトです。DB変更はフロントエンドより先に適用します。共通DBや student-chat のVercelプロジェクトにデプロイしないでください。旧UIへ戻しても追加DB列は残す方式にし、利用データのある列・監査履歴を削除しないでください。
